Response: Time series analysis models data points collected sequentially over time t∈T. Unlike standard statistical modeling, time series data violates the Independent and Identically Distributed (i.i.d.) assumption due to serial dependencies across observations.
Data structures fall into two main representations:
* Regular Time Series: Sampled at uniform intervals Δt (e.g., hourly aggregation, daily sum).
* Irregular / Point Process Data: Events occur at arbitrary timestamps t1​,t2​,…,tn​. Analysis focuses on inter-arrival times τi​=ti​−ti−1​, event counts in time windows, or continuous intensity estimation.
1. Time Series Decomposition
A time series yt​ can be factorized into four primary component processes:
1. Additive Model: Used when seasonal/cyclical variations remain constant regardless of the trend magnitude.
yt​=Tt​+St​+Ct​+ϵt​
2. Multiplicative Model: Used when the amplitude of variations scales proportionally with the trend.
yt​=Tt​⋅St​⋅Ct​⋅ϵt​
Components
   * Trend (Tt​): Long-term directional movement (upward, downward, or neutral) over the entire timeframe.
   * Seasonality (St​): Patterns repeating at fixed, deterministic calendar frequencies (e.g., daily hour-of-day, weekly day-of-week).
   * Cyclicality (Ct​): Non-periodic, longer-term fluctuations driven by macro-factors without a fixed structural length.
   * Residual / Noise (ϵt​): Irreducible random variation remaining after removing structured components.
Decomposition Methods
   * Classical Decomposition: Uses centered moving averages for trend estimation and average ratios for seasonal indexing.
   * STL (Seasonal-Trend Decomposition using Loess): Non-parametric method using locally weighted regression. Handles flexible seasonal changes and is robust against outliers.
2. Stationarity and Transformations
Stationarity requires that the statistical properties of the series remain constant over time.
Weak (Second-Order) Stationarity
A time series yt​ is weakly stationary if it satisfies three criteria:
   1. Constant Mean: E[yt​]=μ for all t.
   2. Constant Variance: Var(yt​)=σ2<∞ for all t.
   3. Time-Invariant Autocovariance: Cov(yt​,yt−k​)=γ(k), depending strictly on lag distance k, not time t.
Strict Stationarity
The joint probability distribution of any sequence (yt1​​,…,ytk​​) is identical to the shifted sequence (yt1​+h​,…,ytk​+h​) for any time shift h.
Diagnostic Tests
   * Augmented Dickey-Fuller (ADF) Test: Tests H0​: Unit root present (non-stationary) vs. H1​: Stationary.
   * KPSS Test: Tests H0​: Trend/Level stationary vs. H1​: Unit root present.
   * Dual Testing Strategy: Confirmed stationarity occurs when ADF rejects H0​ and KPSS fails to reject H0​.
Stationary Transformations
   * First-Order Differencing: Δyt​=yt​−yt−1​ removes linear trends.
   * Seasonal Differencing: Δs​yt​=yt​−yt−s​ eliminates repeating period-s seasonal effects.
   * Variance Stabilization: Logarithmic transform ln(yt​) or Box-Cox transformation λytλ​−1​ stabilizes changing variance (heteroscedasticity).
3. Autocorrelation Analysis
Dependency metrics across time lags govern the structural configuration of parametric models.
   * Autocovariance Function:
γ(k)=E[(yt​−μ)(yt−k​−μ)]
   * Autocorrelation Function (ACF):
ρk​=γ(0)γ(k)​∈[−1,1]
Measures linear dependency between yt​ and yt−k​, including intermediate lag influences.
   * Partial Autocorrelation Function (PACF): Measures direct correlation between yt​ and yt−k​ after partialing out linear correlations of intermediate lags (yt−1​,…,yt−k+1​).

	4. Parametric Time Series Models
Autoregressive Model: AR(p)
Expresses yt​ as a linear combination of its p past values:
yt​=c+i=1∑p​ϕi​yt−i​+ϵt​
Moving Average Model: MA(q)
Expresses yt​ as a linear combination of q past white noise residual shocks:
yt​=μ+ϵt​+j=1∑q​θj​ϵt−j​
Autoregressive Integrated Moving Average: ARIMA(p,d,q)
Combines AR and MA modeling after applying d-th order differencing to achieve stationarity:
(1−i=1∑p​ϕi​Li)(1−L)dyt​=c+(1+j=1∑q​θj​Lj)ϵt​
where L is the backshift operator (Lkyt​=yt−k​).
Seasonal ARIMA: SARIMA(p,d,q) × (P,D,Q)s​
Extends ARIMA by adding seasonal autoregressive (P), differencing (D), and moving average (Q) terms with seasonal period length s.
Multivariate Frameworks
      * VAR (Vector Autoregression): Models dynamic interactions between vector components Yt​=[y1,t​,y2,t​,…,ym,t​]T.
      * ARIMAX / Dynamic Regression: Adds external covariates Xt​ directly to the ARIMA mathematical formulation.
5. Event-Based Time Series & Point Processes
When modeling discrete events rather than continuous metrics, stochastic point processes and structural boundary methods apply:
1. Temporal Point Processes
Events are represented as timestamp sequences T={t1​,t2​,…,tn​}. The process is characterized by its conditional intensity function λ(t∣Ht​), representing the instantaneous event rate at time t given past history Ht​:
λ(t∣Ht​)=Δt→0lim​ΔtP(Event in [t,t+Δt]∣Ht​)​
2. Hawkes Process (Self-Exciting Point Process)
Models cluster-based event patterns where an initial event elevates the probability of subsequent events over a localized time horizon:
λ(t)=μ(t)+ti​<t∑​αγ(t−ti​)
where μ(t) is baseline intensity, α is excitation scale, and γ(Δt)=e−βΔt represents exponential memory decay.
3. Change-Point Detection
Identifies non-stationary structural shifts in distribution, mean rate, or variance across time bounds:
      * Algorithms: Pruned Exact Linear Time (PELT), Binary Segmentation, Bayesian Change-Point Analysis (BCPA).
4. Duration & Hazard Modeling
Analyzes interval length Di​=tend,i​−tstart,i​ using survival analysis metrics:
      * Hazard Function h(t): Instantaneous termination rate given survival up to duration t.
      * Formulations: Weibull parametric regression, Cox Proportional Hazards model.
6. Machine Learning & Deep Learning Frameworks
      * Feature Engineering: Lagged target values (yt−1​,yt−24​), rolling stats (window mean, window standard deviation), cyclical encodings (sin/cos transformations of time components).
      * Gradient Boosted Decision Trees: XGBoost, LightGBM, CatBoost using temporally ordered splitting or Purged Group Time-Series Validation.
      * Recurrent Architectures: LSTM, GRU for temporal sequential dependency tracking.
      * Modern Time Series Deep Learning:
      * Temporal Fusion Transformer (TFT): Multi-horizon architecture designed for static metadata, past observed inputs, and known future features.
      * N-BEATS / N-HiTS: Fully connected neural architectures utilizing basis function expansion for exact trend and seasonal breakdown.
      * PatchTST: Channel-independent Transformer architecture using temporal sub-sequence patching.

Response: Because air raid alert data consists of discrete time intervals with start and end timestamps across multiple regions, standard continuous time series forecasting models like ARIMA or Prophet are usually a poor fit. The data is inherently spatio-temporal point event data marked by duration and spatial propagation.
The optimal approach depends on the core question you want to answer.
Question 1: "An alert just started in my region—how long will it last?"
Recommended Approach: Survival / Duration Analysis (Cox Proportional Hazards, Weibull AFT)
Rather than forecasting values on a fixed grid, duration analysis models the probability density function of time-to-event completion (alert termination).
      * Pros:
      * Built for Duration: Explicitly models hazard rates h(t)—answering questions like "Given an alert has already lasted 45 minutes, what is the probability it ends in the next 15 minutes?"
      * Handles Censoring: Gracefully handles alerts that are currently active when you pull the data.
      * High Interpretability: Features like alert type (if available), time of day, region, or concurrent alerts in neighboring oblasts yield clear proportional hazard ratios.
      * Cons:
      * Single-Task Focus: Only models duration once an alert is triggered; it does not predict when the next alert will occur.
      * Regime Sensitivity: Alerts caused by short ballistic missile threats (15–30 mins) follow fundamentally different distribution shapes than long Shahed drone waves (3–6 hours) or nationwide MiG-31K takeoffs (20–40 mins). Clustering alert types first is often required.
Question 2: "Will an alert happen in Region X in the next 1–3 hours based on current activity?"
Recommended Approach: Spatio-Temporal Hawkes Processes (Self-Exciting Point Processes)
Air raid alerts display strong self-excitation (a wave of strikes excites multiple alerts in sequence) and spatial diffusion (alerts often travel along flight corridors from eastern/southern border regions toward central/western regions).
      * Pros:
      * Continuous Time Precision: Works directly with exact microsecond timestamps rather than forcing data into artificial hourly or daily time bins.
      * Models Excitation & Cascades: Quantifies both baseline risk μ(t) (background threat level) and background-to-region excitation αe−βΔt (how an alert in Kharkiv or Sumy increases short-term risk in Kyiv or Poltava).
      * Mathematically Rigorous: Provides strong theoretical insights into spatial dynamics and threat propagation patterns.
      * Cons:
      * Math & Implementation Complexity: Estimating multi-dimensional spatio-temporal Hawkes parameters requires specialized libraries (e.g., tick or ptpack in Python).
      * Limited Feature Integration: Harder to inject heterogeneous tabular features (like weather or calendar features) compared to machine learning trees.
Question 3: "Can I build a real-time prediction model for alert probabilities across all regions?"
Recommended Approach: Discretized Windowing + Gradient Boosted Trees (XGBoost / LightGBM / CatBoost)
If your goal is an end-to-end predictive pipeline, convert the timeline into uniform time slices (e.g., 15-minute interval bins) and transform the problem into tabular binary classification or multi-label classification across regions.
      * Pros:
      * Feature Engineering Flexibility: Easily engineer rich contextual features: status of adjacent regions in the last k minutes, rolling alert count in the past N hours, rolling average duration, time-of-day cyclical features, and inter-region lag correlations.
      * State-of-the-Art Tabular Performance: GBDTs handle non-linear interactions, regime shifts, and missing attributes far better than deep learning or linear models on tabular feature sets.
      * Production Ready: Simple to deploy as a real-time REST API or automated dashboard.
      * Cons:
      * Information Loss from Binning: Aggregating continuous timestamps into discrete 15-minute or 1-hour intervals sacrifices precision.
      * Class Imbalance: In quieter regions or periods, active alert bins are rare relative to non-alert bins, requiring targeted loss functions or resampling strategies.
Question 4: "How do regional dependencies interact across the entire national network?"
Recommended Approach: Spatio-Temporal Graph Neural Networks (ST-GNNs / Spatial-Temporal Transformers)
Model Ukraine’s administrative regions as nodes in a graph, with edges representing shared borders or known flight vector paths.
      * Pros:
      * Native Spatial Awareness: Directly encodes physical geographic adjacency matrices Aij​ alongside temporal sequences.
      * Multi-Region Coordination: Predicts simultaneous multi-region alert probabilities simultaneously.
      * Cons:
      * High Complexity & Data Requirements: Substantially harder to train, debug, and tune than tree models.
      * Black Box Nature: Harder to interpret structural triggers compared to point processes or hazard models.
